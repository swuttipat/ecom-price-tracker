## Key Decisions

- **2026-08-10 — Workstation created.** Daily competitor price tracking for probiotic
  supplements, replacing manual browse-and-paste. Four stages behind `scripts\run.bat`:
  scrape, store, process, dashboard.

- **Lazada first, alone.** Decided against building all three platforms at once. Lazada was
  proven scrapeable over plain HTTP in a probe before any code was written, so it delivers a
  working end-to-end pipeline immediately. Shopee and TikTok bolt on behind the same schema.

- **Lazada needs no browser.** `https://www.lazada.co.th/{slug}/?ajax=true&q={query}&page={n}`
  returns the page's own JSON: 40 listings per request, 10 of the 11 required fields
  directly (`name`, `brandName`, `sellerName`, `price`, `originalPrice`, `ratingScore`,
  `review`, `itemSoldCntShow`, `categories`, `itemId`). Only subcategory is derived, from the
  category slug being crawled. Full sweep is 36 requests, about 3 minutes.

- **`lang=th` forces Thai product names.** Without it Lazada auto-translates results to
  English for a visitor it reads as non-Thai (`translatedEnQuery` appears in `serverParams`).
  Set via `product_name_language` in `config/settings.json`.

- **Project lives inside OneDrive, with guards, at Max's request.** The flight price tracker
  had to be evacuated to `C:\dev` on 2026-08-09 after OneDrive corrupted its `.git`. Rather
  than move this one out, three specific guards were built: atomic writes via
  `os.replace`, a trailing-newline check that refuses truncated reads, and a conflict-copy
  scan that aborts the pipeline. Plus one manual step: mark the folder "Always keep on this
  device". **When git arrives, use `git init --separate-git-dir C:\dev\git\ecom-price-tracker.git`
  so the object database never sits in OneDrive.**

- **Unattended plan is a self-hosted GitHub Actions runner**, not a GitHub-hosted one. Cloud
  runners use US datacenter IPs, which Shopee and TikTok block and which would return
  non-Thai pricing. A self-hosted runner keeps Max's Thai home IP with the same workflow YAML
  the flight tracker already uses.

- **2026-08-11 — Lazada walled plain HTTP; collector now falls back to a real browser.**
  The second run was blocked by Alibaba's x5sec captcha (`/_____tmd_____/punish`). Ruled
  out one at a time: cookie priming, the exact parameter set Lazada's own JavaScript sends,
  and `curl_cffi` Chrome TLS impersonation were all blocked, while a real browser succeeded
  from the same IP, so it is client fingerprinting, not an IP cool-off. The normal HTML page

  schema, pipeline and dashboard were untouched. Runs go from about 3 minutes to 6 to 8.
  Browser profile is persistent at `%LOCALAPPDATA%\ecom_price_tracking\browser_profile`,
  outside OneDrive.

  so an in-page `fetch()` with no AbortController hung a whole run indefinitely; the JS now

  hides all progress until exit, which made a working script look hung.

- **Silent-failure gap closed the same day.** The first blocked run was too quiet: run.bat
  warned, the warning scrolled past, and the pipeline rebuilt the previous day's data. Now

  11 captured payloads. First combined day: 1,694 listings (Lazada 1,254 + Shopee 440),
  386 brands, 1,001 sellers.
  **What made it work:** never building the search request ourselves. `fetch_via_page()`
  navigates and captures Shopee's own `search_items` responses off the wire. A hand-made

  `item_card_display_sold_count.historical_sold_count` as a **number**,
  `shop_data.shop_name`, `global_cat.catid`). Legacy `item_basic` kept as a fallback.
  - `global_brand` is an OBJECT `{"brand_id":.., "display_name":..}`, not a string. Present
    on 85% of results. Reading it raw leaked dicts into `brand_name`.
  - `is_sponsored` must come from `adsid`/`ads_keyword` only. `icon_in_image.ads_text` is
    the literal string `"Ad"` on **every** result - a UI template label - and trusting it
    marked 100% of the shelf sponsored. Real rate is 51/440.
  - `collect_shopee.py --rebuild` re-parses saved payloads offline; both mapping bugs were
    fixed without a single extra request to Shopee.

- **2026-08-16 — SHOPEE FIXED. It was never Shopee blocking us, it was a fresh tab.**
  Max could see 60 products in his own Chrome tab while the collector failed on the same
  machine, same session, same second. Diagnosis: `BrowserFetcher` opened a **new** tab via
  `ctx.new_page()` and navigated it straight to a search URL. A tab with no history, no
  referer and no scroll gets challenged; the tab he had been browsing in sails through.
  **Fix:** `reuse_tab_matching="shopee.co.th"` - reuse the user's open tab, and only close
  a tab we created ourselves. Collection worked immediately: 116 SKUs, 2 requests, all
  fields clean.
  Two contributing faults fixed the same day: `fetch_via_page()` had **no rate limiting and
  no request counting** (it navigated search pages back to back while every other path in
  the project waits 2-4s), and the Shopee config was cut from 11 page loads to 2.
  **Shopee serves BOTH payload shapes** - the legacy `item_basic` and the newer
  `item_card_displayed_asset`/`item_data`. The defensive mapping handles either; do not
  delete the `item_basic` fallback.
  **Lesson to carry to TikTok: when a page works by hand but not from the collector, the
  difference is usually the tab, not the site.**

  Lazada-only day exposed them:

     counted as delisted: 701 "gone" when the truth was 261 Lazada + 440 uncollected

  2. **Truncated tiles.** The Price-moves summary counted `D.changes`, which the pipeline
     caps at 400 rows for page weight, so 261 delistings displayed as 144. Counts now come
     from `changeCounts`, a full tally the pipeline computes before truncating; the table
     caption says how many of the total are shown.
  3. **Cached dashboard.** `app_data.js` was loaded with a plain `<script src>`, so the
     browser could serve the previous run's data after a fresh collection. It is now
     injected with a `?t=<timestamp>` cache-buster and the page boots on its onload.
  Also: the header named every platform ever collected, so a Shopee-less day still read
  "Lazada + Shopee". It now names only the platforms in today's snapshot.

- **Naming lesson: give Max double-clickable files, not commands with arguments.** He hit
  three separate failures typing paths and args (`run.bat` from the wrong folder, a missing
  `.\` prefix, and looking for a `run-shopee.bat` that did not exist). Shopee is now
  `1-shopee-login.bat` then `2-run-shopee.bat`, numbered in run order.

- **Navigation races are the recurring failure mode in this codebase.** Three separate

  cookies on the context rather than the DOM where possible, wrap every page call in the
  wait loops, and retry `Execution context was destroyed` once after settling before
  treating it as a failure.

- **2026-08-17 — VERIFICATION LESSON: never confirm a chart with `chart.draw()`.** Max
  reported the SKU chart blank. Every "painted=N" check in this project had called
  `chart.draw()` by hand first, which forces a paint and therefore could not detect a chart
  that never renders on its own. The Cowork browser pane does **not** fire
  `requestAnimationFrame` when it is hidden (`rafFiresInThisPane: false`), so Chart.js never
  gets a frame and every canvas reads `painted=0` there regardless of correctness.
  **How to actually verify a chart from now on:** assert the chart object exists, the canvas
  is non-zero, the datasets and axis range are right, and `chart.update()` does not throw -
  then say plainly that visual rendering is unverified and ask Max to look. Do not claim a
  chart renders on the basis of a manual draw.
  Real bug fixed while investigating: `applyChartDefaults()` did
  `Chart.defaults.animation = {duration: 260}`, which **replaces** the object and drops
  `easing`. Now sets `.duration` and `.easing` as properties. Honest caveat: reinstating the
  old line did not reproduce `this._fn is not a function` on demand, so it is not proven to
  be the cause of the blank chart Max saw - only that the code was wrong and the error has
  not recurred since.

- **2026-08-18 - the "search is broken" report was the filter, not the search.** Max searched
  `Bomi` and got 0 results. Tested before changing anything: `Bomi` / `bomi` / `BOMI` / `bOmI`
  / `"  bomi  "` all return **14** identically - the search lowercases both sides and always
  did. The 0 came from the **Price changed only** checkbox: all 14 Bomi listings held their
  price flat over every collected day, so the filter removed them and the empty state said

  Fixed the real defect: an empty picker now reads *"Nothing matched, but 14 would - those
  listings held their price and Price changed only is hiding them"* with a **Show them
  anyway** button that clears the checkbox. A genuinely absent term gets a different message
  naming what is searched (product, brand, seller) and that it is case-insensitive.
  **Also found: the browser caches `index.html`.** Dashboard updates could appear not to land
  - my own test served stale code and reported `matchingSkus(true)` ignoring its argument,
  which only the old build does. Added no-cache meta tags, and `run.bat` now opens the
  dashboard as `file:///.../index.html?t=<random>`. Batch gotcha worth remembering:
  `pushd "..." && set "D=%CD%"` captures the directory from BEFORE the pushd, because %CD%
  expands when the whole line is parsed - pushd, set and popd must be separate lines.
  **Chart rendering confirmed working by Max on 2026-08-18.**

- **2026-08-18 - flat price series were drawn as mountain ranges.** Max charted a Bomi
  listing whose price moved 371.0 -> 370.9 -> 370.8 (0.2 THB across 8 days). Chart.js
  auto-scaled to that 0.2 span, so rounding noise filled the whole plot and **every y-axis
  tick read the same "฿371"** while the table beside it correctly said "flat / 0.0%".
  Fix in `lineChart()`: give the y-axis a floor of **2% of the value** (minimum 1 unit) when
  the data span is smaller, and derive tick decimals from the resulting span (2dp under 2,
  1dp under 20, whole numbers above). `baht()` used to `Math.round()` internally, which
  silently discarded the added precision, so it now takes a decimals argument like `num()`
  and `pct()`.
  Result on that listing: axis 367.19-374.61, 9 distinct tick labels, and the wobble now
  occupies **3% of the plot height instead of 100%** - it reads flat, which is the truth.
  Charts with real variation are untouched (median price still whole baht, promo share still
  0.1pt, listing counts still integers). **General rule: never let an auto-scaled axis
  magnify noise into signal.**

## Platform Notes

- **Shopee** — `/api/v4/search/search_items` returns `403` with `error 90309999` over plain
  HTTP from a home IP. Needs Playwright with a persistent Chrome profile, capturing the XHR
  response inside the browser rather than parsing the DOM. Max logs in himself once;
  credentials are never handled by Claude. `playwright` is not installed yet.
- **TikTok Shop** — reachable but has TikTok-scale anti-bot. Hardest of the three,
  explicitly best-effort.
- **Lazada quirks found on 2026-08-10:**
  - `adFlag` is the **string** `'0'`, which is truthy in Python. `isSponsored` is a real
    boolean. Both go through `common.truthy()`. Getting this wrong flagged all 1,201
    listings as sponsored on the first run.
  - `itemSoldCntShow` is Thai-formatted (`"936 ชิ้น"`) and absent for about 45% of listings.
    `ratingScore` is absent for about 40%. Absence means Lazada shows no badge, not a
    scraping failure.
  - `itemUrl` is protocol-relative (`//www.lazada.co.th/...`).
  - The Windows console is cp1252 and dies on Thai text. `common.py` reconfigures stdout to
    UTF-8 at import.

## Working Notes

- **First collection, 2026-08-10:** 1,201 unique SKUs, 247 brands, 708 sellers, 7 shelves,
  36 requests. Median selling price ฿499 against a ฿790 median list price. 70.6% of listings
  on promotion, average 27.3% off.
- **List prices are inflated.** Median discount 38.5%; 35% of promoted listings claim more
  than 50% off, 2.6% claim more than 80%. `retail_price` is seller-declared, so treat
  `promo_price` as the real number and any discount as a marketing claim.
- **"Unbranded" is 37.6% of the shelf** (452 listings), by far the largest single group.
  Lazada does not require a brand field. `config/brands.csv` can pull known names out of
  product titles as more brands are identified; add aliases there as they come up.
- `data/raw/_payloads/` holds gzipped raw JSON per request. `run.bat rebuild` re-parses a
  day offline, which is how the `adFlag` bug was fixed without re-scraping.
- Dashboard charts are rendered lazily on first tab activation. Chart.js measures a canvas
  inside a `display:none` tab as 0x0 and never recovers, with or without a later `resize()`.
- `run.bat test` runs 15 checks on the day-over-day logic against a synthetic second day.
  All passed on 2026-08-10.
